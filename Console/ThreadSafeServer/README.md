# Thread-Safe Server

Консольное приложение на **C# / .NET**, демонстрирующее организацию потокобезопасного доступа к общему состоянию.

В основе задачи лежит классическая проблема синхронизации **Readers–Writers (читатели–писатели)**.

---

## Задача

Реализован статический класс `Server`, содержащий целочисленное поле:

```csharp id="5ml7ph"
count
```

Для работы с ним предусмотрены два метода:

```csharp id="3e0lhf"
GetCount()
AddToCount(int value)
```

`GetCount()` возвращает текущее значение `count`.

`AddToCount(int value)` добавляет переданное значение к `count`.

К серверу одновременно могут обращаться несколько клиентов из разных потоков.

Необходимо обеспечить следующие условия:

- несколько читателей могут читать значение одновременно;
- читатели не должны блокировать друг друга;
- писатели должны выполнять изменение значения последовательно;
- одновременно изменять `count` несколько писателей не могут;
- во время записи читатели должны ожидать завершения операции записи.

---

## Проблема конкурентного доступа

Без синхронизации несколько потоков могут одновременно обращаться к одной и той же переменной:

```text id="o1d5qj"
             count
               ▲
       ┌───────┼───────┐
       │       │       │
    Reader   Writer   Writer
```

Особенно опасна ситуация с операцией:

```csharp id="d90uwu"
count += value;
```

Такая операция концептуально состоит из нескольких действий:

```text id="6wd4f9"
Прочитать count
       ↓
Добавить value
       ↓
Записать новое значение
```

Если два потока выполняют эту последовательность одновременно, один из результатов может быть потерян.

Это является примером **race condition** — состояния гонки.

---

## Требуемая модель доступа

Для сервера используется модель **Readers–Writers**.

```text id="2ud1e2"
                    Server
                      │
                 ┌────┴────┐
                 │  count  │
                 └────┬────┘
                      │
          ┌───────────┴───────────┐
          │                       │
      GetCount()             AddToCount()
          │                       │
          ▼                       ▼
       Readers                  Writers
          │                       │
          ▼                       ▼
   могут работать          только один
    параллельно             одновременно
```

Главное отличие операций чтения и записи заключается в том, что чтение не изменяет общее состояние.

Поэтому несколько читателей могут безопасно работать одновременно.

Запись изменяет состояние, поэтому требует эксклюзивного доступа.

---

## Правила синхронизации

### Несколько читателей

Допускается ситуация:

```text id="e43oxn"
Reader 1 ─────┐
Reader 2 ─────┼──► count
Reader 3 ─────┘
```

Все читатели получают доступ к значению параллельно.

Они не изменяют `count`, поэтому не создают конфликт друг с другом.

### Несколько писателей

Одновременная запись запрещена:

```text id="4fxxuz"
Writer 1 ──► запись

Writer 2 ──► ожидание

Writer 3 ──► ожидание
```

После завершения первого писателя право записи получает следующий.

Таким образом:

```text id="fr1xtj"
Writer 1 → Writer 2 → Writer 3
```

Запись выполняется последовательно.

### Чтение во время записи

Если писатель изменяет `count`, читатели должны ожидать:

```text id="byksj5"
Writer
  │
  ▼
Запись в count
  │
  ├──── Reader 1 → ожидание
  ├──── Reader 2 → ожидание
  └──── Reader 3 → ожидание
  │
  ▼
Запись завершена
  │
  ▼
Readers получают доступ
```

Это предотвращает чтение общего состояния во время его изменения.

## Общая схема

```text id="wjh7w5"
                    Клиенты
                       │
          ┌────────────┴────────────┐
          │                         │
       Чтение                    Запись
          │                         │
          ▼                         ▼
     GetCount()              AddToCount(value)
          │                         │
          ▼                         ▼
   Shared access             Exclusive access
          │                         │
          └────────────┬────────────┘
                       ▼
                     count
```

Таким образом:

```text id="jv1w7f"
READ + READ    → разрешено
READ + WRITE   → запрещено
WRITE + WRITE  → запрещено
```

## Потокобезопасность

**Потокобезопасность (thread safety)** означает, что объект или метод корректно работает при одновременном обращении из нескольких потоков.

Для данной задачи потокобезопасность означает сохранение корректного значения `count` независимо от количества одновременно работающих клиентов.

Например, если:

```text id="a8uvcp"
count = 0
```

и десять операций последовательно добавляют:

```text id="bl3wxi"
+1
```

ожидаемый результат:

```text id="f20skp"
count = 10
```

Результат должен оставаться корректным даже в том случае, если операции были запущены конкурентно.

## Readers–Writers

Задача является вариантом классической проблемы **Readers–Writers**.

Она возникает, когда несколько потоков используют общий ресурс, при этом существуют два типа операций:

**Readers** — только читают данные.

**Writers** — изменяют данные.

Основное правило:

```text id="wz7z8a"
Readers:
R1 ──────────►
R2 ──────────►     параллельно
R3 ──────────►

Writers:
W1 ─────► W2 ─────► W3     последовательно
```

При активном писателе остальные операции, конфликтующие с записью, ожидают освобождения ресурса.

## Тестирование

Для проверки решения необходимо создать несколько параллельно выполняющихся задач или потоков.

Например:

```text id="llgvtf"
                 Server
                    ▲
                    │
       ┌────────────┼────────────┐
       │            │            │
    Reader       Reader       Writer
       │            │            │
    Reader       Writer       Reader
```

Тестирование должно подтверждать следующие свойства:

- несколько читателей работают параллельно;
- читатели получают корректное значение `count`;
- одновременно работает не более одного писателя;
- писатели не теряют результаты других операций записи;
- читатели не получают доступ во время записи;
- итоговое значение `count` соответствует сумме выполненных операций.

---

## Пример проверки

Начальное значение:

```text id="at9qsm"
count = 0
```

Параллельно запускаются операции:

```text id="1yvk4v"
AddToCount(10)
AddToCount(20)
AddToCount(30)
AddToCount(40)
```

После завершения всех операций ожидается:

```text id="1gm4wk"
count = 100
```

Порядок выполнения отдельных потоков может отличаться, однако итоговое значение должно оставаться корректным.

## Результат

Реализован потокобезопасный доступ к общему состоянию сервера с разделением операций чтения и записи.

Решение обеспечивает:

- параллельную работу читателей;
- эксклюзивный доступ для писателей;
- блокировку чтения во время записи;
- последовательное выполнение операций изменения;
- защиту общего состояния от race condition.

Задача демонстрирует основные принципы конкурентного программирования и синхронизации потоков в C#/.NET.
