# Log Standardizer

Консольное приложение на **C# / .NET** для стандартизации лог-файлов.

Программа обрабатывает лог-файл, содержащий записи в двух различных форматах, преобразует корректные записи к единому стандартному представлению и сохраняет результат в выходной файл.

Невалидные записи сохраняются отдельно в `problems.txt` без изменения исходного содержимого.

---

## Задача

Необходимо привести записи различных форматов к единой структуре:

```text
Дата	Время	УровеньЛогирования	ВызвавшийМетод	Сообщение
```

Разделителем между полями в выходном файле является символ табуляции (`\t`).

Программа должна:

- распознавать два поддерживаемых формата логов;
- извлекать необходимые поля;
- приводить дату к единому формату;
- нормализовать уровень логирования;
- обрабатывать отсутствие вызывающего метода;
- сохранять текст сообщения;
- определять невалидные записи;
- записывать невалидные строки в отдельный файл `problems.txt`.

---

## Поддерживаемые входные форматы

### Формат 1

Пример входной записи:

```text
10.03.2025 15:14:49.523 INFORMATION Версия программы: '3.4.0.48729'
```

Структура записи:

```text
Дата
Время
Уровень логирования
Сообщение
```

Пример разобранных данных:

```text
Дата:                 10.03.2025
Время:                15:14:49.523
Уровень логирования:  INFORMATION
Вызвавший метод:      отсутствует
Сообщение:            Версия программы: '3.4.0.48729'
```

Так как вызывающий метод в данном формате отсутствует, при преобразовании используется значение `DEFAULT`.

---

### Формат 2

Пример входной записи:

```text
2025-03-10 15:14:51.5882| INFO|11|MobileComputer.GetDeviceId| Код устройства: '@MINDEO-M40-D-410244015546'
```

Структура записи:

```text
Дата
Время
Уровень логирования
Идентификатор
Вызвавший метод
Сообщение
```

Пример разобранных данных:

```text
Дата:                 2025-03-10
Время:                15:14:51.5882
Уровень логирования:  INFO
Вызвавший метод:      MobileComputer.GetDeviceId
Сообщение:            Код устройства: '@MINDEO-M40-D-410244015546'
```

---

## Выходной формат

Все корректные записи приводятся к единому виду:

```text
Дата	Время	УровеньЛогирования	ВызвавшийМетод	Сообщение
```

Поля разделяются символом табуляции.

Пример результата:

```text
2025-03-10	15:14:49.523	INFO	DEFAULT	Версия программы: '3.4.0.48729'
2025-03-10	15:14:51.5882	INFO	MobileComputer.GetDeviceId	Код устройства: '@MINDEO-M40-D-410244015546'
```

---

## Нормализация уровня логирования

Входные уровни логирования преобразуются к стандартному набору значений:

| Входное значение | Результат |
|---|---|
| `INFORMATION` | `INFO` |
| `INFO` | `INFO` |
| `WARNING` | `WARN` |
| `WARN` | `WARN` |
| `ERROR` | `ERROR` |
| `DEBUG` | `DEBUG` |

Например:

```text
INFORMATION → INFO
WARNING     → WARN
ERROR       → ERROR
DEBUG       → DEBUG
```

---

## Обработка вызывающего метода

Если поле `ВызвавшийМетод` присутствует во входной записи, его значение переносится в результат без изменения.

Например:

```text
MobileComputer.GetDeviceId
```

Если вызывающий метод отсутствует, используется:

```text
DEFAULT
```

Таким образом:

```text
10.03.2025 15:14:49.523 INFORMATION Версия программы: '3.4.0.48729'
```

преобразуется в:

```text
2025-03-10	15:14:49.523	INFO	DEFAULT	Версия программы: '3.4.0.48729'
```

---

## Обработка невалидных записей

Если строка не соответствует ни одному из поддерживаемых форматов или содержит некорректные данные, она считается невалидной.

Такие строки не добавляются в основной выходной файл.

Вместо этого исходная строка без изменений записывается в:

```text
problems.txt
```

Например, если во входном файле присутствует:

```text
Некорректная строка лога
```

она будет перенесена в `problems.txt` в исходном виде.

Это позволяет сохранить проблемные данные для последующего анализа.

---

## Алгоритм работы

Обработка каждой строки выполняется последовательно:

```text
Входной файл
      │
      ▼
 Чтение строки
      │
      ▼
Определение формата
      │
   ┌──┴───┐
   │      │
Формат 1 Формат 2
   │      │
   └──┬───┘
      ▼
 Извлечение полей
      │
      ▼
 Проверка данных
      │
   ┌──┴──────────┐
   │             │
Корректная   Некорректная
   │             │
   ▼             ▼
Нормализация  problems.txt
   │
   ▼
Формирование строки
   │
   ▼
Выходной файл
```

Для корректной записи выполняются:

1. определение формата;
2. извлечение даты и времени;
3. определение уровня логирования;
4. нормализация уровня логирования;
5. определение вызывающего метода;
6. извлечение сообщения;
7. формирование строки стандартного формата;
8. запись результата в выходной файл.

## Тестирование

При тестировании приложения рекомендуется проверить следующие сценарии:

- корректная запись первого формата;
- корректная запись второго формата;
- преобразование `INFORMATION` в `INFO`;
- преобразование `WARNING` в `WARN`;
- обработка `ERROR`;
- обработка `DEBUG`;
- установка `DEFAULT` при отсутствии вызывающего метода;
- сохранение вызывающего метода для второго формата;
- сохранение исходного сообщения;
- обработка некорректной даты;
- обработка неизвестного уровня логирования;
- обработка строки неизвестного формата;
- запись невалидных строк в `problems.txt`;
- обработка пустого входного файла.

## Запуск проекта

Для запуска требуется установленный **.NET SDK**.

Проверить установленную версию:

```bash
dotnet --version
```

Перейдите в каталог проекта:

```bash
cd LogStandardizer
```

Соберите проект:

```bash
dotnet build
```

Запустите приложение:

```bash
dotnet run
```

Если для проекта реализованы автоматические тесты, их можно запустить командой:

```bash
dotnet test
```
